# Audio: XACT lifted, DirectSound native

Last updated 2026-11-20 (v0.40.2: a stream released with FlushEx flag 4 holds until flushed, so music stops; v0.33.5: a submix buffer's status is its own Play and Stop, so XACT's sound sources free up; voice headroom; object headers reused; v0.33.1: the mix bins saturate at 24 bits, a peak limiter on the stereo fold, the interaural delay by its sign, ADPCM block size settled; v0.33.0: the voice processor as measured on a retail console: 8-point Lagrange resampling, the attenuation curve and gain ramps, the state-variable DLS2 filter, the parametric EQ, the I3DL2 filters, HRTF taps as minifloats routed by route; v0.30.0: the mixer on its own thread, mix bins, envelopes, the DLS2 filter, 3D voices with the HRTF, the I3DL2 reverb, 5.1 output, WMA lifted; v0.25.0: sound output through SDL3, DirectSound streams; v0.15.0: XACT lifted, DirectSound replaced over a software mixer).

The game plays its sound through XACT, Microsoft's audio engine (cues, sound banks, wave banks, notifications), which sits on DirectSound, which programs the Xbox's audio chip (the APU: a voice processor that plays and mixes up to 256 voices, and a DSP that runs effects such as reverb).

```
lifted game code  →  XACT (lifted)  →  DirectSound (native, dsound.cpp)  →  audio engine (audio/)  →  output
                      └ WMA decoder (lifted)   └ 3D calculator, HRTF table (lifted)
```

**XACT is lifted**, like the C runtime and XAPI: its cue logic, variation choices, volume curves and notifications are the original's, exactly. It touches the hardware once: it reads the APU's global sample counter (`0xFE80200C`) as its clock. The lifter turns that into a device-register read (`recompiler-core.md`), and the runtime answers it from the mixer's clock, so XACT's idea of time and the sound it hears agree. Its differential test: 332 functions, 0 mismatches.

**WMA is lifted** (v0.30.0): XACT decodes WMA wave-bank entries through the XBE's own WMA decoder (the `WMADEC` section), which is pure computation over buffers, so it's lifted with XACT: 132 functions. It uses MMX and SSE; the lifter gained what it needed for that (`xadd`, `psraw`/`psrad`, `paddd`, `psubw`/`psubd`/`psubsw`, the saturating packs, `pmaddwd`, `pshufw`, `cvtps2pi`/`cvttps2pi`/`cvtpi2ps`). The wave banks checked so far (5 of the disc's 12) hold only PCM, so no WMA has been decoded yet; the path is there for any that does.

**DirectSound is native** (`recomp/runtime/host/dsound.cpp`): it's the layer that drives the APU's registers, and the APU isn't emulated. Its functions are replaced at the API level, each at its address in the XBE with its original argument size. The pure computation in it is lifted instead, so its values are the original's: `XAudioCalculatePitch`, the PCM and Xbox ADPCM format builders, and the 3D calculator with its HRTF table (below).

## The audio engine

`recomp/runtime/audio/` knows nothing about DirectSound; it has voices, the mix bins and the reverb.

- **Voices** play sample data straight from guest memory (DirectSound's buffers point into it): 8- and 16-bit PCM and Xbox ADPCM, mono or stereo, at any rate.
- **Xbox ADPCM:** IMA ADPCM in 36-byte blocks per channel (a 4-byte header with the predictor and step index, then 32 bytes of nibbles in 4-byte groups interleaved across channels). A block is 64 samples, as DirectSound counts them; the header's sample seeds the predictor. DirectSound's own format builder (`XAudioCreateAdpcmFormat`, `0x1C8C29`) settles the count: `wSamplesPerBlock` 64, and an average byte rate of the sample rate / 64 × 36. (The game plays no ADPCM so far: its wave banks are PCM, all 139 entries of the four on the disc.)
- **Pitch and volume** in the Xbox's units: pitch in 1/4096 octave relative to 48 kHz (a voice's format sets it), volume in hundredths of a decibel. Since v0.33.0 the voice processor follows raddad772's measurements of a retail console's APU (xemu pull request 3105, October 2026) wherever this engine has the same stage; before, these were reasoned guesses. **Resampling** is the hardware's 8-point Lagrange interpolation over the frames at −3 … +4 around the cursor, the weights rounded to 1/65536, the cursor advancing 2^(pitch/4096) in 16.16 fixed point (linear interpolation before). Frames past a non-looping region's end or before its start are silence; a loop wraps. A voice keeps its last 16 decoded frames, so a stream's interpolation still reads a packet already retired.
- **Mix bins** (v0.30.0): the mix is the APU's 32 bins, each a block of floats: the six speakers (front left, right, centre, LFE, back left, right), the crosstalk canceller's four inputs (bins 6-9), the I3DL2 reverb's input (bin 10), then the other effect sends. Each channel of a voice goes to the bins it names at the voice's volume plus the bin's, as the APU attenuates: in 1/64 dB steps. Since v0.33.0 through the hardware's curve: the gain (in 1/16384) follows straight lines between whole decibels through a table of round(4095 · 10^(−k/20)) rounded down, and from 48 dB a straight line to silence at 63 dB (`0xFC0`); 0 is unity (0xF00 gives 12/16384 where 10^(−att/1280) gives 16). A route's gain moves from the last block's in 32 steps over the first 32 samples, as the hardware ramps it across a frame, and a voice just started fades in from silence over its first 32.
- **Envelopes** (v0.30.0, `SetEG`): the amplitude envelope, as the APU runs it: delay, attack, hold, decay and release in units of 512 frames (16 ticks of its 1500 Hz envelope clock), sustain 0-255. The attack rises linearly, the decay falls exponentially (about 64 dB over its time) to the sustain level, the release falls linearly from where it is to silence and then stops the voice. `StopEx` with `DSBSTOPEX_ENVELOPE` starts the release; `FlushEx` with its release flags releases a stream and, with flag 2, flushes it when the release has played (or at once, when the stream takes new packets first); with flag 4 holds it until a flush (Streams, below). Without an envelope a release is a stop. The game sets releases of 187 and 281 units (2.0 and 3.0 s). The multi envelope (pitch and filter modulation) isn't applied: the game doesn't use it.
- **The voice filter** (v0.33.0; a two-pole DLS2 low-pass from v0.30.0, the EQ not applied). DirectSound's `SetFilter` (`0x1CC93A`, read from the XBE) packs DSFILTERDESC into the voice's registers: FCA = coefficient 1 << 16 | coefficient 0, FCB = 3 << 16 | 2, the mode into MISC bits 17:16, Q (`& 7`) into 20:18; a 3D voice's mode 0 becomes 3, and its FCB is the 3D data's filter coefficients. The hardware filter is a state-variable filter at 48 kHz: frequency coefficient f = 2^(FC/4096) to a 1024th of an octave, then to 1/65536, at most 0xFFFF/65536; each step rounded to 1/16 of a 24-bit sample, halves up. As the **DLS2 low-pass** (its low output) the damping is FC1/32768, unity passband at any resonance; as the **parametric EQ** a peaking filter, y = x + G·q·band, bits 31:16 the signed gain G = gain/8192, q = 2^(−Q). By mode: mono 1 DLS2 from FCA, 2 EQ from FCB, 3 both; stereo channel 0 from FCA, channel 1 from FCB (mode 3 as 1: not measured); 3D voices below. The filter's steps run low, high, band each sample at 48 kHz, as in xemu's filter, which the measurements corrected and were checked against (what they removed from it, an input scale of sqrt(q/2 + 0.01) and a cubic waveshaper, marks it as the Chamberlin filter, single-rate); the measurements don't state the order themselves. The game sets the EQ on two voices.
- **3D voices** (v0.30.0): see below.
- **Regions:** play regions, loop regions, looping, the play position, stopping at the end of a non-looping region.
- **Submixes** (v0.21.0): a `DSBCAPS_MIXIN` buffer is a submix voice with no sample data. Voices sent to it with `SetOutputBuffer` mix into its input (channel for channel; a mono submix takes the sum) at their own volume, and it plays that input with its own volume, mix bins and 3D processing. Since v0.30.0 a voice feeding a submix still feeds its own bins too, which carry its effect sends (the game's 3D sounds send to the reverb from the source and through the submix to the speakers), and a submix plays from its creation: XACT never calls `Play` on its submixes, and they sound on the console. One level: a submix feeding another stops the runtime.
- **A submix's status** (v0.33.5): `GetStatus` on a submix buffer reports it playing only between a Play and a Stop of its own, as the original's does (the buffer's voice state, `CMcpxBuffer_GetStatus` at `0x1CDAFC`, which nothing sets for a buffer never played), though it mixes what feeds it from the moment it's made. XACT's 3D sound sources are submix buffers it never plays; it calls a source busy while a cue holds it or its buffer's status says playing (`0x1C3A03`), and the game keeps a pool of 48 sources and reuses the free ones. Before v0.33.5 the status was always playing: no source ever came free, and after the 48th sound (the end of the intro) the game played nothing more through XACT. Only Bink's sound, which goes to DirectSound directly, was still heard.
- **Headroom** (v0.33.5): `SetHeadroom`'s millibels come off the voice's volume, as DirectSound keeps the two (`0x1C5E00`, `0x1C5DAB`: the figure it programs is volume − headroom), in the mix and into a submix. A voice starts with the original's default (`0x1C8249`): 600 (6 dB), or 0 for a 3D voice (flags `0x200010`) or a submix or effects-input buffer (`0x182000`). XACT's streams keep the 600; Bink sets its buffer's to 0. Before v0.33.5 headroom was stored and never applied, so everything XACT played was 6 dB louder than on the console: the mix passed full scale (569 clipped samples in 280 seconds, v0.33.1's figure). With it, 200 seconds through the intro, menus and a fight peak at 0.65 of full scale and none clips.
- **Streams** (v0.25.0, `CreateSoundStream`): XACT plays its wave banks through DirectSound streams. A stream is a voice that plays packets (XMEDIAPACKET) of guest memory one after another as one signal, the interpolation running across their edges. With no packet left it's starved: silent, still running, and the next packet carries on; after `Discontinuity` it stops instead when the packets run out. The stream object is the original's shape where callers look (its first words are CDirectSoundStream's vtables, `0x20A038` and `0x20A028`), so XACT's calls through the vtable (`Process`, `GetStatus`, `Discontinuity`, `Flush`) reach the replacements at those methods' addresses; the setters are the buffer's. A finished packet is reported as the console's DPC reports it, and only where one could run, below DISPATCH_LEVEL (`DirectSoundDoWork`, `Swap`, the game's waits): the completed size and status (`S_OK`, or `E_ABORT` when flushed) into the packet's words, its event signalled, the stream's callback called. A completed packet frees its place in the stream at once, as the APU's does, though its report waits for a DPC. `GetStatus`, `Pause` (including mode 3, resume when the voice starts) and `FlushEx` follow the original's code (`0x1CA7AD`, `0x1CB290`, `0x1CA73B`). **Stopping a cue** (v0.40.2): XACT stops a stream with `FlushEx` flag 4 (and 1, not waiting): the original marks the voice (`0x1000`), releases its envelope, and when the release has played (`0x1CB01A`) holds the stream (`0x2000`): `GetStatus` then reports `DSSTREAMSTATUS_ENVELOPE` (`0x80000`), and `Process` queues a packet without starting the voice (`0x1CB1C2`); XACT, seeing that status (`0x1C274C`), flushes it (`Flush`, the vtable's seventh, from `0x1C3FA5`), which clears both flags. Before, the runtime flushed when the release ended, never reported the status, and started the voice again at XACT's next packet, so a stopped track played on: each pause added another copy of the pause music over the level's. Flag 2 still flushes when the release ends. `QILIN_AUDIO_STATS=1` logs the streams and buffers playing once a second (each stream's channels, rate and volume). Since v0.41.3 the log always has, for the first two minutes, every 10 s, the voices playing, the mix's peak, and the frames queued for the device and its rate trim, and any sound device added, removed or changing format (so a report of sound stopping says which side stopped). `GetVoiceProperties` (streams and buffers) returns what the original reads back from the APU's voice: each bin's attenuation as DirectSound programs it, unused entries bin −1 at −10000, the pitch, zero 3D values; a 3D voice's properties stop the runtime. Pause mode 2, time stamps, output packets and a format change with packets attached stop the runtime.
- **Buffers' other calls** (v0.30.0): `SetFrequency` (the pitch for the rate, 0 the format's own), `GetCurrentPosition` (the play position, and the write position with it: the APU reads the data as it plays), `Lock` (pointers into the buffer's data, which is the game's own memory, wrapping at its end; from the play position or the whole buffer by its flags) and `Unlock`.
- **Tests** (`qilin_audio_tests`, CI): PCM playback, end of data, volume, looping, half-rate playback with interpolation, mix bins, the ADPCM decoder and sizes, submixes, streams, the envelope's attack and release, the DLS2 filter, the parametric EQ (DC unchanged, the centre frequency doubled at G = 1), a 3D voice's routes, taps and I3DL2 paths (the console's own impulse figures: 0.875 × 0.125^n and 0.25 × 0.75^n), the tap decoding and attenuation curve at the measured points, the fade-in ramp (0, ¼, ½, ¾, 31/32 at samples 0, 8, 16, 24, 31), the Lagrange weights at ½, the reverb (silent before its delay, decaying, finite).

## 3D sound

The game positions its sounds with DirectSound's own 3D calculator (`IDirectSound3DCalculator_Calculate3D`, `GetVoiceData`) and its full-HRTF table (`DirectSoundUseFullHRTF`), all lifted, so the voice settings are the console's. It hands them to `Set3DVoiceData` and `Use3DVoiceData`, about 4,000 times in five minutes of play; v0.30.0 applies them as the original does:

- **The data** (DS3DVOICEDATA) is a flags word then fields, each copied when its flag is set, as `CDirectSoundVoice_Set3DVoiceData` (`0x1C5E64`) does: bit 0 the dword at +4, 1 at +8, 2 at +0x0C and +0x10, 3 at +0x14 and +0x18, 4 at +0x1C and +0x20, 5 at +0x24, 6 the two angles at +0x28 and +0x2C, 7 the filter coefficients at +0x30 and +0x34.
- **Volumes**, as the original's volume calculation (`0x1CBDC1`) programs them, with d*k* the dword at 4·*k*: a base of d1 + d2; the crosstalk front bins d7 + d5 + d3 more, the crosstalk back bins d7 + d4, the centre d7 + d6 + d3, the I3DL2 send d8; each sum held to −10000…0 and added to the bin's volume.
- **Pitch:** d9 is added (Doppler).
- **The head-related filter:** when the angles change, the runtime calls the original's HRTF lookup (the function the game installed at `0x1E3B88`, lifted) with them, before the mixer's lock is taken; it returns the two ears' coefficient sets from the XBE's table: 31 taps and the interaural delay in frames. Since v0.33.0 the taps are read as the hardware reads them (measured): sign and magnitude, a 3-bit exponent and a 4-bit mantissa, (16 + m) · 2^(e − 1) / 2048, or m / 2048 with exponent 0 (0x40 is 1/16, 0x7F 31/32), applied as written. (v0.30.0 took them as two's complement × 1/512, a scale set by ear; `0x9F`, in the straight-ahead filter, read as −0.19 where the hardware's −0.015. The straight-ahead filter now passes 0.42 at DC in each ear, the same both sides, and 3D sounds are about 8 dB quieter in play than in v0.32.) The voice's signal goes through each ear's filter, the far ear delayed (by the delay's sign, below). The hardware routes by route, not by bin: the left ear on routes 0-1, the right on 2-3, the voice itself on 4-7. DirectSound orders a 3D voice's bins crosstalk front left, back left, front right, back right, centre, I3DL2, LFE, so the ears reach the crosstalk inputs on their sides. A 3D voice's **I3DL2 filters** (measured): a pair of one-pole low-passes, y = (1 − a)·x + a·y′, a = FCB bits 15:0 / 65536 for the direct path (routes 0-4 and 6, so also the ears' input) and bits 31:16 for the room path (routes 5 and 7: the reverb send), in every filter mode; mode 1 adds the DLS2 and mode 2 the EQ, both from FCA. The coefficients come from the 3D data (bit 7) and, until it sets them, from `SetFilter`'s FCB. The delay's sign names the ear, as DirectSound's lookup gives it (the left table's delay past the azimuth split, else the right's negated): positive delays the left ear. Checked over five minutes of play: in 7.96 million blocks with a delay, the delayed ear's filter was the quieter one every time.
- **The crosstalk canceller** (the effects image's effect 1, which turns the binaural crosstalk bins into speaker feeds) isn't applied: its four inputs go to their speakers as they are, which is what headphones want. Since v0.33.0 the 3D data's filter coefficients (bit 7) are the I3DL2 filters' (above).

## Effects

The game downloads the standard effects image (18,012 bytes), with the I3DL2 reverb as effect 0 and the crosstalk canceller as effect 1. The DSP isn't emulated; the reverb is native (`audio/reverb.cpp`), driven by `SetI3DL2Listener`'s parameters, the I3DL2 model: the input (bin 10) through the room level and its high-frequency roll-off at the HF reference; early reflections, four taps after the reflections delay; and the late reverb after the reverb delay, diffused by two allpasses (by the diffusion) into eight feedback delay lines (30-67 ms, a Householder mix), which decay −60 dB over the decay time, faster at high frequencies by the HF ratio. Its four outputs go to the front and back speaker bins. The game turns it on with the generic room (room −1000, decay 1.49 s, HF ratio 0.59, reflections −1219 after 7 ms, reverb −1800 after 11 ms). *Not the DSP's own algorithm:* the levels and the room's character follow I3DL2's parameters, not the effect image's code.

## Output

The mix runs on its own thread (v0.30.0): it keeps the mix up to the audio clock (the host's steady clock) every 4 ms, and every DirectSound call catches it up first, so a sound plays as long as on the console and `GetStatus` reports its end when it comes. One lock covers the mixer's state; guest code (a stream's callback, the HRTF lookup) never runs under it, and a guest thread never waits for it while running guest code, so the scheduler (`runtime.md`) can't deadlock on it.

The speakers go to SDL3 (`recomp/runtime/platform/audio_out.*`) on the default playback device, 48 kHz floats:

- **5.1** (v0.30.0) where the device has six or more channels: the six speaker bins as they are, in SDL's order, which is the Xbox's (front left, right, centre, LFE, back left, right). The OS carries them to HDMI, optical or a surround headset; the Xbox's real-time Dolby Digital encoder (the `DOLBY` section) isn't needed. The console's audio setting the game reads (`ExQueryNonVolatileSetting`) is then surround with Dolby Digital (`0x00010002`), as on a console set up for it, so the game and DirectSound's 3D calculator pan to the back speakers themselves.
- **Stereo** otherwise (setting: stereo): the centre at −3 dB into both sides, the back bins into their sides, the LFE left out.
- **Full scale** (v0.33.1): the mix bins saturate where the console's do, 24-bit, after the voices and after the effects. The game's own mix passes full scale at loud moments (in the attract sequence its front bins alone reach 1.33, its busiest speaker bin 1.73), and saturates there on the console too. The stereo fold is ours (the console's stereo downmix isn't known) and would add to it: 71 samples past full scale in the speaker bins became 515 in the fold. A look-ahead peak limiter (1.5 ms; the gain comes down by the steepest line that holds every frame in the window to full scale, and recovers with a 50 ms release) takes that out: below full scale the fold is unchanged sample for sample, and in a 280-second recording the samples at full scale went from 569 (clipped) to 47 (held there by the limiter). 5.1 output has no fold and no limiter.
- `--audio-channels 2|6` chooses; `--mute` (and `--headless`) play nothing; `--dump-audio FILE.wav` writes the stereo mix.

The queue starts with 60 ms of silence, so the device never runs dry, and is held there by trimming the playback rate a little (at most 0.5%, inaudible), which absorbs the drift between the sound card's clock and the host's. After a stall, frames older than the queue's limit (four times the cushion) are dropped, as they'd have played already on the console. The device buffer is asked to be 512 frames.

## Not applied, and not modelled

Named once at run time when the game first uses them: LFOs (`SetLFO`; the game doesn't use them), the multi envelope, effect sends past the reverb's (the image has no other effect), mix-bin headroom other than 0 (the game sets 0 on every bin).

**The DSP's own effects** (the reverb's algorithm and the crosstalk canceller) need the image run as the console runs it. What that takes, from the game's image (18,012 bytes, dumped at `DownloadEffectsImage`): its program is stored scrambled (the code region from `0x804`, 0x2690 bytes, is high-entropy; DirectSound unscrambles it as it loads it into the DSP's memory), so (1) DirectSound's image loader, unscrambling included, lifted or read and reimplemented; (2) a DSP56300 interpreter or a recompiler for the image (fixed, so it can be recompiled like the XBE); (3) the GP's surroundings: the mix bins as the DSP reads them, its output to the speakers, the 32-sample frame sync, DMA; (4) DirectSound's parameter writes into the DSP's memory (`SetI3DL2Listener` and the crosstalk settings converted to the effect's state). Until then the reverb is native and the crosstalk canceller's inputs go to their speakers as they are.

Stopping the runtime if reached: submixes of submixes, effect-input buffers, buffers with their own memory, `DSBPLAY_SYNCHPLAYBACK`, stopping at a time stamp.
